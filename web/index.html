Nigeria Public Procurement Intelligence

Nigeria's published public procurement records, audited and turned into a validated analytics database and an interactive dashboard, with every figure reconciled to SQL.

Open the dashboard See the code on GitHub

What this is

Nigeria's Bureau of Public Procurement publishes procurement records on its open contracting portal, NOCOPO, in the Open Contracting Data Standard (OCDS): plans, tenders, awards, contracts and implementation. This project takes one bulk export of that data, audits it, loads it into a PostgreSQL database and answers seven questions about suppliers, competition, budgets, timing, procuring entities, implementation and data quality.

  • 108,277 published releases: updates to procurement records
  • 98,454 procurement processes, one record each, with the portal's test entity set aside
  • 665 procuring entities (ministries, agencies and other public bodies)
  • 9,800 suppliers with a usable supplier ID

Releases are dated from 3 May 2021 to 29 July 2026. The export's package date is file metadata, not the date of every record.

Key findings

Patterns in the published records. Each figure gives the records it is based on, and none is a finding about anyone's conduct.

More than two in five tenders record a single bidder

44.0%

of tenders record one tenderer; the median is 2 tenderers. Under National Competitive Bidding the rate is 39.6% (10,129 tenders).

Based on 17,253 tenders with a plausible recorded count. The source does not say whether the count is bids received or bids found responsive.

Competition page

Supplier value is spread widely, except in emergency procurement

29.0%

of attributable award value goes to the ten largest suppliers (Herfindahl index 139.4, low on its scale). In Emergency procurement the largest supplier holds 61.4%.

Based on 13,537 awards with a usable supplier ID. 2,226 awards (20.4% of award value) have none and are left out, so this is a lower bound.

Supplier concentration page

The typical award is close to budget, but a small group is far above it

0.93

is the median award as a ratio of its budget line. Yet 227 processes (1.5%) awarded more than ten times their budget hold 49.8% of the compared award value.

Based on 15,574 processes with one usable budget line. A budget is a plan, not spend.

Budget versus award page

Award value sits with a few entities

76.0%

of award value sits with the ten largest procuring entities; the largest alone holds 40.6%.

Based on 665 procuring entities. Value shares depend on a handful of very large awards.

Entity benchmark page

Timing can be measured for under half of processes

97 days

is the median time from tender start to award. Only 45.2% of the processes it applies to publish the two valid dates it needs.

Based on 7,462 processes. Results describe the processes that published valid dates, not the rest.

Procurement-cycle timing page

Implementation reporting is broad

87.2%

of contracts have some implementation data published (milestones or transactions); 2,081 have none.

Based on 16,221 contracts. This is reporting coverage, not a measure of contract performance.

Implementation and lifecycle page

Possible scale errors (DQ-21). 45 awards (₦509.5bn, 15.5% of award value) look out of scale with their own process record, for example a decimal point that seems to be missing. They are kept in every figure and flagged. Without them the ten largest suppliers hold 26.1% rather than 29.0%, and the median award-to-budget ratio stays at 0.93.

How it was built

  1. Raw OCDS JSONOne bulk export, pinned by its checksum and never modified.
  2. StagingLoaded as published, with data-quality flags set in SQL. Nothing is deleted.
  3. Core modelEntities, suppliers and one snapshot per process, taken from its latest releases.
  4. Analytics viewsOne view per metric, each with its own eligibility rules and record count.
  5. DashboardsA Power BI report and this web version, both reading only the validated views.

PostgreSQL holds the logic; Python loads the file and runs the checks. One command, python/run_pipeline.py, rebuilds the whole database from the raw file and re-runs every check. The Power BI report reads the views through a read-only database role. This web version exports the same views to static data files and computes each figure in your browser.

Why you can trust the numbers

  • 21 data-quality issues logged and handled. Questionable records are flagged rather than deleted, and left out only of the metrics they would distort.
  • Eligibility per metric. There is no single "clean" dataset: each metric states which records qualify, and every figure shows how many records it is based on.
  • 259 automated validation checks from the raw file to the analytics views, all passing on a clean rebuild.
  • All 177 dashboard figures reconciled to SQL, in the Power BI report and again in this web version.

Run the check in your browser

The check page recomputes every dashboard figure from the published data files and compares each one with its SQL value.

How to read the dashboard

  • 1 Executive overview: the headline figures and how complete the record is.
  • 2a Supplier concentration: how award value is shared among suppliers.
  • 2b Competition: how many tenderers processes record, by method and entity.
  • 3 Budget versus award: awarded value against the recorded budget line.
  • 4 Procurement-cycle timing: how long stages take, where valid dates allow.
  • 5 Entity benchmark: procuring entities compared on the same measures.
  • 6 Implementation and lifecycle: whether implementation data was published, and how far processes progress.
  • 7 Data quality and coverage: which data issues affect which figures.
Records (n)
Each card shows its result and the number of records it is based on. Records that do not meet a metric's eligibility rules are left out of that metric only, so the count differs from card to card. Tap or click a card to see its exact value.
Filters
Most pages have filters at the top, such as procuring entity and procurement method. A filter changes only the charts whose data carries that field, and it is kept in the page address, so a filtered view can be shared. On a phone, tap Filters to open them.
Flagged awards (DQ-21)
Awards flagged as possible scale errors stay in every figure. Pages 1, 2a and 3 add a fixed panel with key figures without them, and page 5 has a switch to leave them out.

Limitations

  • Data as published. The figures describe one export of what was published to the portal. A newer download will differ, and a missing record is not evidence that an event did not happen.
  • Coverage gaps. 82.3% of processes were published at planning stage only, so later-stage figures describe a minority of processes. Timing covers only processes with valid dates, and supplier figures leave out awards without a usable supplier ID.
  • Patterns, not conclusions. The figures show patterns in reported data. They do not explain why a pattern exists, and nothing here suggests wrongdoing by any entity, official or supplier.
